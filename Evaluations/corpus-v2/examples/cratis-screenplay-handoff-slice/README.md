Use `registration-example.json` as the batch A success/refusal input and expected observations. Its revision identifies `accepted.esm.json`, the **example contract**, exported from `model/` at `--scope Library.Authors`. The registration and list slices are exported together here so the journey can check their shared outcome. It is not production approval. For the browser phase the target owner provides a separately authorized local rendered or implemented Authors app. Install the fixture's pinned Playwright and Chromium. Set `AUTHORS_TARGET_ADAPTER` to the file URL of the owner's trusted module exporting async `startIsolatedAuthors({revision,authorId})`. It starts the real target in an empty disposable namespace with that fixed new ID, returning `authorsUrl` on loopback, `editorStorageState` for the permitted editor and async `close()`. Run `npm run test:journey`. It fails if no target is supplied. It uses the batch A browser assertion, not a mock app. Run batch A's distinct backend refusal assertion too; disabled Add is not evidence of server refusal.

No renderer, extension lock, target approval or real host is supplied by this model. Confirm generated command/query bindings, permission, validation, form and durable result on the target before declaring parity. Do not run extraction, force rendering or use a shared namespace to fill those gaps.
