# 0004 - `@cratis/ai` route shape and generated-package layout

Status: Accepted
Related: `/Volumes/Code/Cratis/ai-consolidation-plan.md` Section 6 (the `@cratis/ai` npm package),
Section 6.4 (route shape), risk #12. `Documentation/migration-status.md` flagged this as one of two
decisions still open before Phase 3b could start.

## Context

Phase 3b (`@cratis/ai`) needed two decisions the plan itself calls out as high-stakes and hard to
reverse once commands exist: the HTTP route prefix baked into every generated proxy (risk #12 -
"changing it later breaks both products at once"), and how the generated tree sits inside the
published package. The plan's own Section 6.4 table already worked through the route options and
recommended `SegmentsToSkip=1` (`/api/a-i/...`) over `SegmentsToSkip=2` (`/api/...`, collision-risk
with a product's own routes) - this record adopts that recommendation and records why, plus a layout
detail the plan did not anticipate: `Cratis.Arc.ProxyGenerator.Build`'s `SkipOutputDeletion=false`
(deliberately chosen per Section 6.3, so a deleted command cannot leave a stale proxy behind) wipes
its entire output directory on every build - which cannot be the package root, or it takes the
package's own `package.json`/`tsconfig.json`/`rollup.config.mjs`/hand-written `index.ts` with it.

## Decision

1. **Route prefix: `/api/a-i/...`**, via `CratisProxiesSegmentsToSkip=1` (skip only the leading
   `Cratis` namespace segment). `RecordAgentSessionUsage` generates as `/api/a-i/usage`;
   `AgentUsageByWeek.RecentWeeks` as `/api/a-i/usage/trends/recent-weeks`. Distinct and
   collision-proof against either product's own routes, and - because both products load the same
   published proxy - byte-identical in both hosts by construction.
2. **Generated output goes to a `generated/` subfolder of `Source/Cratis.AI.Proxies`, not the
   package root.** `CratisProxiesOutputPath` is `.../Cratis.AI.Proxies/generated`. The package root
   carries `package.json`, `tsconfig.json`, `rollup.config.mjs`, and a hand-maintained `index.ts`
   barrel that re-exports from `./generated/...` - none of it touched by
   `SkipOutputDeletion=false`, all of it wiped if it had shared the generator's own output path.
3. **The generated folder tree drops the redundant `AI/` prefix** a literal `Cratis.AI.Usage.Trends`
   namespace mapping would otherwise produce (a package already named `@cratis/ai` does not need an
   `AI/` folder inside it), via `--namespace-root=Cratis.AI=.`. This is a folder-layout convenience
   only, independent of the route decision above - routes are still derived from `SegmentsToSkip`,
   not from `NamespaceRoot`.
4. **The CI drift gate (`publish.yml`'s `verify` job) checks only `Source/Cratis.AI.Proxies/generated`**,
   not the whole proxies package - the hand-authored files at the package root legitimately change on
   their own and must not trip a gate meant to catch a stale *generated* proxy. The gate rebuilds
   `Cratis.AI` first (`dotnet build`, Debug) so the diff is against a freshly regenerated tree, not
   the checked-out tree compared with itself. The diff itself uses `git diff -I '^// @generated by
   Cratis'` rather than a bare `git diff --exit-code`: every generated file's header stamps the
   generation wall-clock time, which differs by construction on every run even when nothing the
   generator actually produced changed - a bare diff failed on every single run, always, which the
   first real CI run on this PR proved immediately. The header's own content hash (unaffected by
   `-I`) is what actually reflects whether the generated content changed.
5. **`@cratis/ai` is versioned and published in lockstep with `Cratis.AI`** (plan Section 6.5): the
   same `publish.yml` release run sets both to the version `cratis/release-action` determined,
   `publish-dotnet-packages` and `publish-npm-packages` run in parallel, and `verify-published` fails
   the run if the two results diverge (one published, the other did not) - never letting the pair
   drift out of version-sync silently.

## Consequences

- Every future command/query the package grows lands under `/api/a-i/...` automatically - no route
  decision needed per PR, only per command-shape choice (which segment names it, via the type's own
  namespace).
- Adding a new top-level namespace folder (e.g. `Providers/`, once provider commands/projections
  land) needs one new line in `Source/Cratis.AI.Proxies/index.ts` - documented inline in that file as
  a manual step the drift gate does not catch (it only checks `generated/`, not the hand-written
  barrel), so a forgotten export line fails as a missing export at the consuming end, not a CI
  failure here. Worth a follow-up decision if that proves error-prone in practice.
- `CopyLocalLockFileAssemblies=true` had to be added to `Cratis.AI.csproj` for proxy generation to
  work at all: the generator resolves `Cratis.AI.dll`'s dependency closure (`Cratis.Chronicle`,
  `Cratis.Fundamentals`, ...) through a reflection-only `MetadataLoadContext`, which needs every
  referenced assembly physically present next to `Cratis.AI.dll` in the build output. A plain class
  library does not copy its NuGet dependencies locally by default (an ASP.NET Core app, which is what
  Direct's and Studio's own proxy-generating projects are, does) - without this property the
  generator crashes attempting to resolve `EventSourceId<T>`'s base type from a `Cratis.Chronicle` it
  cannot find. Worth carrying forward to any other plain-library Cratis package that ever generates
  proxies of its own.
- `RecordAgentSessionUsage`'s own command validator was simplified as a direct consequence of getting
  this far enough to actually generate real TypeScript: Arc's `IModelGraphValidator` already applies
  each `ConceptAs<T>` property's own `ConceptValidator` automatically (the same traversal a query
  argument gets), so the command-level `RuleFor(_ => _.CostUsd!.Value)...` rules this class used to
  carry were pure duplication - and, it turned out, broke generation: the ProxyGenerator translates a
  validator's property-chain expression literally, and `CostUsd!.Value` became a nonsensical
  `c.costUsd.Value` access on a TypeScript property already flattened to a plain `number`. Validate
  at the concept, not the command, for this class of property - both for correctness and because the
  generator cannot currently handle the alternative.

## Alternatives rejected

- **`SegmentsToSkip=2` (`/api/...`, no `a-i` prefix).** Rejected per the plan's own Section 6.4
  reasoning: risks colliding with a product's own `Providers`/`Usage`-named routes once Direct or
  Studio migrate, with no compile-time signal that it happened.
- **Generated output at the proxies package root, `SkipOutputDeletion` left at the generator's own
  default (`true`).** Would have avoided the wiped-hand-authored-files problem, but reintroduces
  exactly what `SkipOutputDeletion=false` exists to prevent (plan Section 6.3): a deleted command
  leaving a stale, silently-wrong proxy in a published package.
