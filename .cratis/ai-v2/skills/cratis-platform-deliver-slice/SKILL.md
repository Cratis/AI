# Deliver one observable change

1. Start with one actor, intent, visible result and refusal. For Authors: a permitted catalog editor submits Aster and sees one new row without reloading; blank input adds nothing. If [Hand off the accepted slice](../cratis-screenplay-handoff-slice/SKILL.md) supplied an accepted revision, carry its caller, examples and target forward. Model acceptance is neither permission to render nor evidence that the application works. For code-first work no `.play` file is needed. Read references/slice-contract.md if the request only says “build CRUD.” **Done:** the same examples drive backend and screen acceptance.
2. Keep hand-written contracts under the business feature. Give `RegisterAuthor(Id, Name)` to [Declare a command](../cratis-arc-declare-command/SKILL.md). For event-backed registration give `AuthorRegistered(Name)` to [Record an event](../cratis-chronicle-record-event/SKILL.md) **for the declaration only**; the command returns the fact and the integration appends it. Give blank `Name` to [Validate a command](../cratis-arc-validate-command/SKILL.md). **Done:** server dispatch as the editor records exactly one fact at the submitted `AuthorId`; a separate blank dispatch returns a `Name` error and records none. Do not infer this from a disabled button.
3. Give the fact and required row to [Project a view](../cratis-chronicle-project-view/SKILL.md): `Author.Id` comes from the source and `Author.Name` from the payload. Materialize rows for a collection-backed list; a passive fold alone does not populate the collection. Give `Author(Id, Name)` to [Expose a query](../cratis-arc-expose-query/SKILL.md) for the static, observable `AllAuthors` query over that same scoped collection. Give write and read permissions to [Authorize a request](../cratis-arc-authorize-request/SKILL.md), not the client. **Done:** the editor's initial result excludes the new ID; the same subscription's next relevant emission includes the submitted ID and name. An unauthorized caller cannot write or read the protected data.
4. Give the built contracts to [Generate proxies](../cratis-arc-generate-proxies/SKILL.md), then the actual generated command and query paths to [Bind the slice in React](../cratis-arc-react-bind-slice/SKILL.md). Use [Display a list](../cratis-components-display-list/SKILL.md) when the page needs columns or row selection. **Done:** the screen type-checks against generated contracts, submits once, and renders the query result without a hand-edited proxy, second fetch path or locally invented row.
5. On an approved disposable host, open Authors, submit Aster, wait for one row **before reload**, then reload and confirm it persists. Check blank input on fresh state; if the UI prevents submission, keep the independent server refusal check. **Done:** command result, keyed history, materialized row, live query and browser agree. If the first failing boundary is unknown, give the correlated case to [Diagnose a slice](../cratis-platform-diagnose-slice/SKILL.md) rather than replaying events or re-rendering a model.

Run `dotnet test -c Release` in the application's backend-spec project; expect the append and refusal checks to pass. For a Playwright journey, run `npx --no-install playwright test journey.spec.ts` (substitute the application's journey filename) in the UI project against the disposable host. Expect the row before and after reload. A mocked story cannot prove that path.

Requires Playwright Chromium for the browser proof: check `npx --no-install playwright install --list` for the matching browser. If absent, run `npx playwright install chromium` using the project's Playwright version or report the journey unverified.
