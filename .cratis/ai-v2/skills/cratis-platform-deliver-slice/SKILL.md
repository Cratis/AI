# Deliver one observable change

1. Start with one actor, intent, visible result and refusal. For Authors: a permitted catalog editor submits Aster and sees one new row without reloading; blank input adds nothing. If `cratis-screenplay-handoff-slice` supplied an accepted revision, carry its caller, examples and target forward. Model acceptance is neither permission to render nor evidence that the application works. For code-first work no `.play` file is needed. Read references/slice-contract.md if the request only says “build CRUD.” **Done:** the same examples drive backend and screen acceptance.
2. Keep hand-written contracts under the business feature. Give `RegisterAuthor(Id, Name)` to `cratis-arc-declare-command`. For an ordinary write use the existing store and skip Chronicle. For event-backed registration give `AuthorRegistered(Name)` to `cratis-chronicle-record-event` **for the declaration only**; the command returns the fact and the integration appends it. Give blank `Name` to `cratis-arc-validate-command`. **Done:** server dispatch as the editor records exactly one fact at the submitted `AuthorId`; a separate blank dispatch returns a `Name` error and records none. Do not infer this from a disabled button.
3. Give the fact and required row to `cratis-chronicle-project-view`: `Author.Id` comes from the source and `Author.Name` from the payload. Materialize rows for a collection-backed list; a passive fold alone does not populate the collection. Give `Author(Id, Name)` to `cratis-arc-expose-query` for the static, observable `AllAuthors` query over that same scoped collection. Give write and read permissions to `cratis-arc-authorize-request`, not the client. **Done:** the editor's initial result excludes the new ID; the same subscription's next relevant emission includes the submitted ID and name. An unauthorized caller cannot write or read the protected data.
4. Give the built contracts to `cratis-arc-generate-proxies`, then the actual generated command and query paths to `cratis-arc-react-bind-slice`. Use `cratis-components-display-list` when the page needs columns or row selection. **Done:** the screen type-checks against generated contracts, submits once, and renders the query result without a hand-edited proxy, second fetch path or locally invented row.
5. On an approved disposable host, open Authors, submit Aster, wait for one row **before reload**, then reload and confirm it persists. Check blank input on fresh state; if the UI prevents submission, keep the independent server refusal check. **Done:** command result, keyed history, materialized row, live query and browser agree. If the first failing boundary is unknown, give the correlated case to `cratis-platform-diagnose-slice` rather than replaying events or re-rendering a model.

For the backend scenario run `dotnet build Specs --configuration Release -warnaserror`, then `dotnet test Specs --configuration Release --no-build` in the backend example. For the separate live proof run `npm run test:journey` in the slice example with its isolated host adapter configured. A command scenario, passing model spec or mocked story cannot substitute for that journey.
