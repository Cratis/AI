# `arc-proxygenerator` options, types and ownership

Source: `Cratis/Arc.TypeScript`: `Source/Tools/ProxyGenerator/parseSourceOptions.ts`,
`Documentation/proxy-generation/{configuration,type-mapping,validation,file-index-tracking,low-level-manifest}.md`.
The CLI reads source with the compiler API; it never calls a running server.
Options accept `--option value` and `--option=value`; a missing or empty value
is rejected; `--help` prints usage. The scaffold script is in `proxy-generation.md`.

## Required

| Option | Meaning |
| --- | --- |
| `--project <tsconfig>` | `tsconfig.json` of the project declaring the artifacts (absolute path) |
| `--artifacts <folder>` | Discovery root; only exported classes below it count; use the folder given to `discover()` |
| `--output <folder>` | Existing directory; equal to or containing the artifacts root means co-located output |

## Route alignment (must match the server)

| Option | Default | Server equivalent |
| --- | --- | --- |
| `--root-namespace <ns>` | none | `discover(folder, { rootNamespace })`; also prefixes generated model folders |
| `--segments-to-skip <n>` | `0` | `generatedApis.segmentsToSkipForRoute` |
| `--api-prefix <prefix>` | `api` | `generatedApis.routePrefix` |
| `--skip-command-name-in-route` | off | `includeCommandNameInRoute: false` |
| `--skip-query-name-in-route` | off | `includeQueryNameInRoute: false` |

`--root-namespace App` writes models under `App/...`; after upgrading, the
generator removes the old unprefixed files it owns.

## Output and behavior

| Option | Effect |
| --- | --- |
| `--use-proxy-file-suffix` | Name files `*.proxy.ts`; required for co-located output |
| `--js-import-specifiers` | `.js` extensions in local imports for native Node ESM; leave off for Vite and bundlers |
| `--emit-interfaces` | Interfaces instead of model classes; loses decorated model hydration |
| `--skip-react-hooks` | Server-only proxies: no `@cratis/arc.react` import and no `use*`/`when` hooks |
| `--scalar-concept-subclasses` | Type indirect and generic concept subclasses as their underlying value |
| `--skip-index-generation` | No `index.ts` barrels (automatic when co-located) |
| `--skip-output-deletion` | Keep stale generated files |
| `--metadata <file>` | Write server artifact metadata (absolute path) and infer undecorated bindings |
| `--use-generated-metadata` | Infer the same bindings for client-only generation |
| `--check-metadata` | Read-only: fail when the `--metadata` module no longer matches source |
| `--type-mapping <Type>=<package>[#<export>]` | Import a type from another package instead of generating it; repeatable |
| `--watch`, `--watch-poll-interval <ms>` | Regenerate on edits; poll default 1000 on macOS, 5000 elsewhere, `0` disables |

## What the generator recognizes

| Server declaration | Client type |
| --- | --- |
| `String`, `Number`, `Boolean`, `Date` | `string`, `number`, `boolean`, `Date` |
| Fundamentals `Guid`, `DateOnly`, `TimeOnly`, `TimeSpan` | the same Fundamentals types |
| `ConceptAs<T>` | its underlying type (`TaskId extends ConceptAs<Guid>` becomes `Guid`) |
| Decorated models | generated classes (or interfaces) |
| Arrays, string/number enums, string-literal unions | arrays, enums, unions |
| `@derivedType('id')` classes and their bases | emitted with the same declaration |

Discovery skips `index.ts`, `given/`, `dist/`, `node_modules/`, `for_*/` and
symbolic links. Unsupported shapes fail with a source diagnostic, not silently.

## Client validators

The generator copies literal, unconditional `ruleFor` chains from the
constructors of `@validator(Target)` classes into generated validators, for
commands and for queries that declare an explicit `argumentsModel`. Client-safe
rules: `notNull`, `notEmpty`, `minLength`, `maxLength`, `length`,
`emailAddress`, `phone`, `url`, `matches`, `greaterThan`,
`greaterThanOrEqual`, `lessThan`, `lessThanOrEqual`, with messages. `when`,
`unless`, `must`, `mustAsync` and anything needing runtime evaluation stay on
the server and produce a diagnostic. The server validates every request anyway.

## Ownership of files

Every generated file starts with `// @generated by Cratis. Source: ... Hash: ...`.
Never edit such a file; the next run replaces it. The generator removes only
files carrying its header and never touches hand-written files, so a hand-written
file at a generated path is a conflict to resolve, not something to overwrite.

## Low-level definitions

`defineCommand`/`defineQuery` have Zod schemas, so the analyzer cannot see their
output types. Declare `clientOutput: { output }` on each definition, write a
version 1 JSON manifest with `exportClientManifest(server)` from
`@cratis/arc.core`, then run the older positional CLI form with absolute paths:
`arc-proxygenerator <manifest.json> <output-folder>`. That form reads JSON only
and never imports the application; export does not call handlers, validators or
authorization callbacks.
