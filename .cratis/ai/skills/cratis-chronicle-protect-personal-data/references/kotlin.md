# Use a Kotlin personal concept

Mark the personal value type with `@Pii(description = "Customer email address")`, not the routing ID. Use a synthetic customer, record the event and obtain its stored model. In an authorized coroutine call `store.readModels.release(instance)` with the correct subject. Separately test `store.compliance.deleteEncryptionKey(subjectId)` on that disposable subject. Read afresh rather than inspecting the already released object.

Do not put general encryption and subject-owned PII marking on the same personal field. Choose the intended key owner. A personal concept can carry the policy, but a source ID must remain routable and must not itself be a private personal value. Verify the emitted schema and the released result independently.
