# Benchmark recovery on an owned application

1. Pin a known implementation and accepted model revision. Freeze the authorized, sanitized intake packet, a ground-truth behavior ledger (actor, fixture state, input, result and effect), and a structural inventory keyed by full address and kind. Give each run the same packet and scope but withhold the answer key until scoring. Use separate empty comparison workspaces.
2. For each run, align recovered elements to truth one-to-one. Record exact matches, owner-confirmed renames (same meaning and identity), partial matches and missing elements; count unmatched recovered elements as invented. Publish counts and the denominator (all in-scope truth elements), for example `8 exact + 1 rename / 12`, plus partial, missing and invented counts. Use the same matching rules across runs.
3. Replay the same behavior ledger against each rebuilt target using the [black-box replay](../../cratis-modeling-trace-existing-behavior/references/blackbox-intake.md). Report passed / all expected behavior rows and executed / all expected rows, with failed and untested counts. An unexecuted or partly checked row stays open, never in the passed numerator. Keep behavior and structural coverage separate; a renamed match is not evidence of execution.
4. Keep the dated comparison outputs with their revisions, input digest, run conditions and row-level decisions so another reviewer can reproduce the comparison. Don't change the denominator to fit the reconstruction.
