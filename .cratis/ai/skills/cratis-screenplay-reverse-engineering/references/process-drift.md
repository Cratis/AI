# Process drift

Use when a model is accepted and the observed system has since changed. Do not rebuild the
model. The question is whether the system still does what the model says (process drift), not
whether its structure changed (architecture drift).

**Input:** the watermark recorded with the model (`evidence-format.md`, Watermark) and the
current state of the same sources: two OpenAPI documents, two binary or app versions, two
capture sets, or, when source is offered, `<commit>..HEAD` (`cratis-screenplay-legacy-extraction`,
`re-entry-and-passes.md`). The diff between the two states is the work list.

## Source-diff scope helper

Run `node scripts/drift-scope.mjs change.diff evidence-map.json` for JSON work lists;
`node scripts/drift-scope.mjs --self-test` checks a synthetic library drift case and the rejection rules.
The map projects evidence rows into `flows: [{id, evidenceIds, paths}]` and carries
`watermarks: {from: {revision, inputDigest}, to: {revision, inputDigest}}`. Paths are
repository-relative, case-sensitive exact paths or globs (`*` within a segment,
`**` across segments); include shared dependencies in every affected flow's paths.
This map is an index of evidence, not a replacement for the evidence rows.

The helper accepts Git unified diffs with unquoted `diff --git a/... b/...` headers
(and trimmed hunk bodies). It preserves hunk locators and checks both old and new paths.
Artifact hints take precedence: Cratis-generated TypeScript with both `@generated by
Cratis` and `DO NOT EDIT` markers in the diff, lockfiles, scene.json/stage-scene.json,
.cratis-render.json and bin/obj/dist output are structure-only. An unchanged-content
rename (100% similarity, no hunks) and indentation/blank-line-only hunks are also
structure-only; other refactors are not guessed from syntax. All remaining changes,
including unknown files or header-only changes, are conservatively process work.
Unmapped process paths become new-flow candidates; added public static C# methods
supply symbol hints. Empty diffs and missing watermarks/evidence mappings fail closed.

These are scope hints, not semantic proof: generated markers must be present to exclude
proxies, artifact/formatting changes can still affect behavior, and the keep list means
no process hunk matched the supplied mapping. Reconcile artifacts with their source and
inspect uncertain changes before a no-drift verdict. The helper echoes both watermarks;
it never advances the accepted one. The self-test fixture is a synthetic library application: two process hunks in mapped flows, an indentation-only hunk, an unmapped added file that yields a new-flow candidate, and header-only generated, lockfile and scene hunks.

## Steps

1. Compare watermarks per feature. Unchanged features are reported "unchanged since
   <watermark>" and not touched.
2. For each touched feature, classify every hunk of the diff:
   - **process**: a command, field, rule or validation message, authorization, event, state
     change, read-model field, job, side effect or screen field was added, changed or removed;
   - **structure only**: a rename, move, refactor, layering, dependency or formatting change
     that leaves observable behavior alone. Report these as one count and never model them.
3. Re-derive only the flows a process hunk touches, from entry point to persisted or visible
   effect, with the probes of `probing-and-naming.md` for the changed commands and queries.
   Keep evidence ids stable; list retired ids.
4. Output two lists. The **model delta**: slices, rules and events added, changed or removed,
   with evidence ids. The **behavior changes** in business words ("a refund after 30 days is now
   rejected"), each with its locator and old versus new value.
5. Give a verdict per feature: `no drift`, `drift: model update proposed` or
   `drift: needs owner decision`. Every change is a question for the owner; an accepted decision
   is not edited from the diff. Append the new watermark only to features that were reconciled.
