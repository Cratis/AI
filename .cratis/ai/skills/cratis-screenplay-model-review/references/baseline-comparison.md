## Compare agent exposure

Requires Screenplay 6.39.0 (`screenplay --version`) for automatic comparison. For MCP, discover the connected `screenplay` server's `serverInfo.version` and native tool names and input schema; CLI and server versions can differ. On an older but agent-capable tool (6.15.0+, see the shipped [agents block](../../cratis-screenplay-toolchain/references/agent-exposure.md) and [capability manifest](../../cratis-screenplay-toolchain/references/capability-manifest.md)), upgrade, or inspect both complete models by hand and label the result manual; never promise the report on an older tool. Verify the baseline commit, model root and candidate revision first: a wrong or empty folder is not evidence of removal. Review read-only.

**CLI.** `screenplay diff <before> <after>` (text) or `screenplay diff <before> <after> --format json` over the two model roots. It is part of model comparison, not single-model validation, export, build or runtime authorization.

- Text: `Added Query Projects.Registration.List.All` under `Agent exposure (1):`, then `Agent exposure change: yes.`. A complete no-change result says `Agent exposure change: none.`.
- JSON adds `difference.agentExposure`: read `complete`, `hasExposureChange`, `beforeAvailability`, `afterAvailability`, `changes`, `matching` and `notCompared`, independently of the structural `complete` and `hasSemanticChange`.
- Exit **0** means a comparison was produced, including one with additions or an unknown exposure verdict; **2** means it could not run (bad arguments, unreadable source, incompatible persisted application identities). No exposure-specific exit 1. `PLAY0978` (`NewlyExposedAgentOperation`) and `PLAY0979` (`WidenedAgentOperation`) are reserved, not emitted warnings to clear or suppress.

**What the rows mean.** Only bound explicit `agents` entries are compared, not all declared, public or authorized commands and queries. Only `added` is newly allowlisted; `removed` leaves. A retained query whose required scope changes `write` → `read` now admits read-token holders: `scopeChanged` with `scopeChange: widened`; the reverse is `narrowed`. Commands require write. `descriptionChanged` is separate, untrusted authored data; non-scope rows have `scopeChange: none`. Both metadata rows can occur for one retained operation. Any row sets the change verdict true, not necessarily new or broader access. Identity mode matches kind plus persisted bound ID within one application, so identity-preserving moves and renames retain membership. Address mode matches kind plus canonical qualified name with no usable ID: a rename looks like removal plus addition, with no inferred continuity. Reordering entries, or spelling a resolved reference short or qualified, is not a change. A `narrowed` row is not proof of safety, a successful export proves neither permission nor enforcement, and the review records the tool and version that produced the comparison.

**Unknown versus empty.** Both whole semantic compilations must succeed. A successfully compiled model with no `agents` or an explicitly empty allowlist is known empty for comparison. An error anywhere on either side gives that side `compilationFailed`, `complete: false`, `hasExposureChange: null` and no guessed rows, for example `Agent exposure change: unknown; before Available, after CompilationFailed.`. Empty rows alone prove nothing, and exit 0 does not make it a verdict. Obtain the complete roots, inspect compiler diagnostics on the failing side (`screenplay <model-folder> --warnaserror --no-color`; separate warnings from compilation errors), fix the cause such as an unresolved target (`PLAY0966`) or ambiguous name (`PLAY0967`, qualify it), recompile, then re-diff the intended revisions. A partial comparison or cached manifest is no substitute.

**MCP is opt-in, not additive.** For revision sources call the discovered `semantic-diff`, for example `{"before":{"path":"/work/repo-main/Screenplay"},"after":{"workspace":"active"},"includeAgentExposure":true}`. For a retained proposal against its disk baseline call `read-proposal` with `{"proposalId":"<proposal-id>","view":"agent-exposure-diff"}` and do not apply it. Both return `schema: "agent-exposure-diff/1"`, `comparisonLevel: "explicit-agent-allowlist"`, revisions, matching, availability, verdict and a bounded `page` of findings. This selects exposure **instead of** the ordinary structural response; call again without the flag (or false, or `view: "semantic-diff"`) for structure. Continue the same selection with `nextOffset` as `offset` and echo `sourceRevision` as `expectedSourceRevision`; revision diffs pin the ordered pair and reload both sources. Count limit is 1–200, within a 192 KiB source-page bound. On a stale-revision refusal (`StaleRevision`, or a `StaleRevision:` message from `read-proposal`) discard pages and restart; on `PendingOperation` stop for explicit recovery; `IncompatibleRevisions` is not evidence of continuity. `ResponseTooLarge` for a single oversized finding is a refusal, never a truncated success. MCP refusals are not CLI exit codes.

**What to do with a finding.** Report operation and kind, before and after, revision, consequence and an edit request to the owner. For an unintended addition, ask to remove its allowlist entry, not the operation; for an intentional query that should stay write-token-only, ask to restore `scope write`; verify intent on removals and description edits, then repeat the diff. Separately inspect signature/contract and inherited authorization, including inherited module, feature and operation authorization, plus tenant and availability boundaries, even with no delta: a changed signature or authorization alone is a manual access concern, not an automatic widening finding. The comparison doesn't compute authorization, transitive impact, handler behavior or runtime equivalence. An unchanged manifest proves none of these. The reviewer does not repair or edit automatically.
