# Measure one Elixir append and follow it to the kernel

Add the OpenTelemetry SDK and exporter in the application when traces must leave the process; the Chronicle client API dependency alone does not export them. Configure the resource service name and the `:trace_context` propagator. For append duration, attach one handler to `[:cratis, :chronicle, :client, :append, :stop]` with `:telemetry.attach/4`. Read `measurements.duration` in native time units and convert it with `System.convert_time_unit/3`. A stop can carry `error: true`; count it separately rather than treating every stop as success.

Record a bounded outcome and duration, not event contents or source IDs. `[:chronicle, :observer, :lag]` is a different event; an append duration is not delivery lag. Append a synthetic event inside an active span, then find the corresponding kernel span under the same trace. The outbound interceptor propagates W3C trace context for the calling process. If the trace breaks, check that the application started an SDK, the exporter is configured and the active context reached the process making the call. On the kernel side, the built-in meter subscriptions are `Cratis.Chronicle`, `Microsoft.Orleans` and `Grpc.AspNetCore.Server`. On the Elixir side, `Cratis.Chronicle.Client` is the span scope, not a meter to attach with `:telemetry`.
